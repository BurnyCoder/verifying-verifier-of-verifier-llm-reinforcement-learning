# Can a newer frozen Qwen judge detect a false correction?

27 November 2026 · Development extension specified after the original seed-17 comparisons and before inference with these judges. The original held-out analysis has its own checkpoint manifest and decision rule. [Original preregistration](preregistration.md) · [Run inventory](run-inventory.md)

The first experiment changed which judge rewarded a trainable solver. This follow-up first changes the weights inside all three **frozen** judge calls and fixes the solver's written answers. It asks whether an auditor can identify a corrupted number while retaining the correct verdict on the solution. Only a separate online comparison can measure what a solver learns from that auditor. The proposed mechanism and the alternative that the newer model merely becomes better at arithmetic make different predictions on evidence-only twins. [Evidence intervention](matched-depth-protocol.md) · [Original training evidence](reviews/depth-diagnosis.md)

## Model selection and hardware

Compare Qwen2.5-1.5B-Instruct as a same-runtime control with Qwen3.5-4B, Qwen3.5-9B and Qwen3.8-27B. The latter is a recent open-weight dense Qwen model. Its GGUF alone exceeds the GPU's memory. Try it with partial GPU offload and mapped system memory. Full GPU placement of a smaller model is a hypothesis pending a load measurement. We use published text weights, no vision projector and no learned role adapters. Quantization, chat template, model size and generation family covary. The comparison estimates the performance of deployable configurations. [Qwen2.5](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct-GGUF) · [Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B) · [Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B) · [Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B)

Pin the GGUF repository revision, artifact name, SHA-256 and exact byte size for every model. Use standard Q4_K_M for the first three models and the publisher's UD-Q4_K_M for the 27B model. Use the same llama.cpp CUDA release, a single request slot, a 2,048-token context and up to 48 generated tokens per call. Use native chat templates with thinking disabled, greedy decoding and the same demonstrated user/system messages. Score all malformed or truncated replies under the original parser. Keep raw completions and returned token counts. A conversion of Qwen2.5 controls for the runtime change from the original bitsandbytes model. [Pinned model and artifact identifiers](../src/study/frozen_models.py) · [llama.cpp release](https://github.com/ggml-org/llama.cpp/releases/tag/b12807) · [Qwen3.8 non-thinking mode](https://huggingface.co/Qwen/Qwen3.8-27B#instruct-or-non-thinking-mode)

Test models serially on the same laptop. Record runnable placement, load time, available VRAM, prompt and generated tokens, prompt-processing and decoding durations. A prompt-time metric on a partially offloaded model is end-to-end inference time. It does not isolate GPU kernel execution. Record startup or allocation failures and the exact device placement. A four-call timing pilot uses a public worked problem. If the mean exceeds 30 seconds per call after load, retain the pilot and omit that model from the full screen on this host. Timing excludes model download and initialization. Use the same rule for every model.

## Cases, endpoints and decision

1. **Natural replay.** For each feasible model, give the complete chain the same 32 archived starting-solver traces. J2 reads that model's actual J1 report and J3 reads its actual J1 and J2 reports. Record each depth's verdict and whole-report accuracy, false accepts, false rejects and malformed reports. Count J2-to-J3 fixes and harms on the same responses. Any gain here leaves the saved solver answers fixed.
2. **Balanced replay.** Use 32 distinct problems from the confirmed arithmetic family, positions 96 through 127 (zero-based) of the deterministic development-confirmation stream. On each, compare a correct trace with one incorrect intermediate step. Each model sees the same two traces and generates its own chain. Report balanced solution-verdict accuracy at every depth. Its denominator includes both traces for every problem.
3. **Evidence intervention.** On the same 32 problem IDs, use the existing evidence-twin generator, alternating valid and invalid solver solutions and sound and flawed J1 reports. Both J2 twins contain the same solution verdict. J3 must return both complete checker-correct records, including the first bad field and its replacement. Score both visible twins and score both again with the J2 evidence masked. All model inputs are independent requests. Ground truth enters only scoring and the construction of the controlled examples. The primary offline endpoint is visible whole-pair accuracy. Its denominator is the number of problem pairs. [Twin constructor](../src/study/judging.py) · [Independent field labels](../src/study/records.py)
4. **Fresh confirmation.** Rank feasible newer candidates by whole-pair accuracy, then balanced J3 verdict accuracy, then total measured generation time on the screen. Run the first-ranked candidate and the same-runtime control on 64 distinct confirm-stream problems at indices 256 through 319. Use paired resampling by problem, jointly resampling both balanced traces or both twins. Report the two differences with descriptive 95% percentile intervals from 10,000 resamples. Repeated use of the original 32 natural traces is diagnostic. The fresh confirmation is the selection-independent comparison. Neither phase reads the original sealed test population.
5. **Conditional solver training.** If the winner strictly exceeds the same-runtime baseline on both confirmation point estimates (whole-pair accuracy and balanced J3 verdict accuracy), train fresh seed-17 Qwen2.5-1.5B solver adapters with either its J2 or its J3 as the frozen reward. Keep initial solver, four completions, 256 updates, prompt order and generation ceilings matched. Save all reward vectors and measure whether the solver improves on the original common development questions. The trained solvers must be evaluated directly. If either offline comparison fails to improve, record the gate outcome and the two unstarted online arms. Evidence for the auditing hypothesis also requires visible pairs to outperform their masked copies. An interval spanning zero is inconclusive about a population-level improvement. [Online training design](preregistration.md)

Every model has the same output format and input evidence. Native templates can tokenize that evidence differently. The 27B quantizer differs, and offload changes latency. Report failures, selection, all candidates, all outcomes and costs even if no model improves.
