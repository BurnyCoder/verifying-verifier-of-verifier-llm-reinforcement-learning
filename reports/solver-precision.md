# Solver precision and pretraining-only alternatives

27 November 2026. The owner asked whether less compression or a Qwen checkpoint released before reinforcement learning could be used on this GPU. This hardware check is separate from the seed-17 judge-depth comparison. Publish the choice and measurement before the corresponding model calls.

Try the original Qwen2.5-1.5B-Instruct at its native BF16 precision with the confirmed frozen Qwen3.5-4B judge resident on the same 8 GB GPU. If BF16 cannot run a full update, try 8-bit. A second candidate is Qwen3.5-2B-Base at NF4. Qwen identifies that file as pretraining-only. The original Instruct model has undergone post-training. Its model card and the family report do not establish that it is free of prior RLVR. Changing its storage precision does not change its training history. [Original solver](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct) · [Qwen2.5 training report](https://arxiv.org/html/2412.15115v1#S4) · [Pinned pretraining-only candidate](https://huggingface.co/Qwen/Qwen3.5-2B-Base/tree/b1485b2fa6dfa1287294f269f5fb618e03d52d7c)

Use the train split for the feasibility probe and the published model files. Check CUDA placement, four real solver samples, the frozen judges' replies, a GRPO optimizer step, wall time and peak device memory. Record fit failures as hardware observations. A candidate may fit but give malformed answers or a constant reward group. One update supplies no estimate of learned accuracy. Keep the two registered solver arms on a common original NF4 initialization. A future precision or backbone comparison would need its own matched training arms.

Run the original NF4 model as a hardware reference. Before any disposable update, score 16 greedy traces from positions 256–271 of the calibrated train stream with each configuration. Use the same demonstrated user messages, each model's native chat template and the exact complete-trace checker. The 2B candidate loads its pretrained text weights for this arithmetic-only task. Check for missing language weights. The program records the two processes' dedicated allocations and the solver's peak PyTorch allocation. Reproduce with `uv run --extra gpu study solver-fit`. [Transformers Qwen3.5 text model](https://huggingface.co/docs/transformers/model_doc/qwen3_5)

The Qwen2.5 family report describes answer matching and execution feedback in preparing DPO preference pairs, and a learned reward model for its online GRPO phase. This gives a concrete reason to prefer the explicitly pretraining-only release when prior reward training is itself the scientific question.
