# Preflight scientific and implementation review

The GitHub preregistration is commit 2e80aa1. Implementation and the protocol paper were public on GitHub and Hugging Face before the first study-model call.

The primary measurement is full-trace correctness. A solution may have the correct root and a false earlier step. A separate audit bit judges whether the preceding reviewer was right. A fixture reproduces the worked evidence-only swap and checks that endorsing a sound rejection gives the solver zero reward. The generator assigns canonical IDs before creating variants and holds out long and balanced-root expressions. Exact labels use the numbered expression tree. A second evaluator in the tests checks generated arithmetic independently.

The independent-vote and recursive conditions match the number of judge calls and generation ceilings. The recursive prompts are longer. Recorded token counts and CUDA-event elapsed times permit an efficiency comparison. CUDA-event durations include idle gaps between submitted kernels. The shared backbone limits conclusions about independent model families. The evidence score covers the stated numerical certificate. Correct labels can be obtained without a faithful internal reasoning process.

The checkpoint test uses a small random CPU transformer, the real TRL optimizer and the normal training CLI. It interrupts immediately after a complete group checkpoint, resumes, and compares final parameters and raw group assignments with uninterrupted training. This is a pipeline test, separate from the study outcomes.

The visible and masked evidence pairs have opposite correct soundness bits. Once both reviews are masked, the two public prompts are identical. A deterministic reviewer that returns identical records on those prompts cannot earn whole-pair credit. The masked comparison tests information flow. Natural error corrections, newly introduced errors, flat voting and downstream solver accuracy are needed to judge practical value.

The sampler excludes the canonical IDs of the two published worked examples, including commutatively equivalent spellings, before admitting any problem to a study split.

The test seal compares the final adapter with the digest recorded at its development evaluation. It checks every raw four-completion group, verifies the reward comparisons saw identical ordered arithmetic prompts within seed, and checks direct and top-down judges saw identical traces and preceding reports when trained on the same corpus. Final evaluations validate each participating fitted adapter, including frozen judges. A second arithmetic test executes each public operation line independently and changes all values from a chosen step onward to check first-error localization.

Training recovery accepts the last optimizer checkpoint with a complete Trainer state, RNG state, scheduler, optimizer and adapter. The ordinary CLI regression test leaves a torn subsequent checkpoint on disk before resuming the earlier complete one. It compares all subsequent policy outputs and the final adapter tensors against an uninterrupted run. [Transformers Trainer](https://huggingface.co/docs/transformers/main_classes/trainer)
